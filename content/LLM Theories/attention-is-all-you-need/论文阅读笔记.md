# Attention Is All You Need

## 论文信息

| 属性 | 值 |
|------|-----|
| 标题 | Attention Is All You Need |
| 作者 | Ashish Vaswani, Noam Shazeer, Niki Parmar, Jakob Uszkoreit, Llion Jones, Aidan N. Gomez, Łukasz Kaiser, Illia Polosukhin |
| 会议/期刊 | NeurIPS |
| 年份 | 2017 |
| 链接 | https://arxiv.org/abs/1706.03762 |
| 阅读日期 | 2026-06-17 |

## 一句话总结

> 提出 Transformer 架构，完全基于自注意力和多头注意力，替代 RNN/CNN 以提升并行性并缩短长程依赖路径。用 8 块 P100 训练 3.5 天，在 WMT2014 英德翻译上达到 28.4 BLEU。

## 核心问题

- RNN 序列模型计算是顺序的（无法并行），长程依赖需要 O(n) 步才能传递信号
- CNN 虽然可以并行，但捕捉长程依赖需要堆叠多层，路径长度仍是 O(log n)，且计算/显存随感受野增长

## 关键洞察 / 创新点

1. **Self-Attention 替代 RNN/CNN**：完全用注意力机制建模序列依赖，常数级路径长度 O(1)，高度可并行
2. **Multi-Head Attention**：多个注意力头并行关注不同子空间，增强表达能力
3. **Scaled Dot-Product Attention**：引入 $\frac{1}{\sqrt{d_k}}$ 缩放因子，防止内积过大导致 softmax 梯度消失
4. **Positional Encoding**：用正弦/余弦编码注入位置信息，替代 RNN 的隐式时序建模
5. **Encoder-Decoder 架构**：自注意力编解码 + 交叉注意力，统一的模块化架构

## 技术细节

### 为什么叫Scaled Dot-Product Attention

Attention 要的是"query 和 key 有多匹配"，必须是个标量分数，才能丢进 softmax 当权重。点积正好给标量；叉乘给的是向量，维度都对不上（叉乘只在 3 维有定义，而这里 d_k=64）。所以这里是 100% 的点积，不存在"叉乘 attention"。

第一个定语 "Dot-Product"——规定"用什么函数衡量 Q/K 匹配度"
  - 取代的是 Additive Attention（Bahdanau 2014）：score(q,k) = vᵀ tanh(W₁q +  W₂k)，用一个小神经网络算分数
  - 论文选 dot-product 的理由很直白：它就是矩阵乘法，GPU/TPU 上飞快；additive 要逐对跑小网络，慢
  - 所以 "Dot-Product" 这三个字是冲着 "Additive" 说的

  第二个定语 "Scaled"——规定"要不要给分数降温"
  - 取代的是不带缩放的 dot-product attention（Luong 2015 风格）：直接 softmax(q·k)V
  - 不缩放在 d_k 小时没事，但 d_k 一大（这里 64），点积方差 = d_k，数值爆掉 → softmax 饱和 →
  梯度消失
  - 除以 √d_k 把方差拉回 1，这就是 "Scaled" 的活
  - 所以 "Scaled" 是冲着 "unscaled dot-product" 说的
  
### MHA 的两头显存压力（训练 vs 推理）

MHA 在每个头各存一份"东西"，这带来两个不同场景的显存压力，解法也不同。两头都 memory-bound——瓶颈是显存搬运/存储，不是算力不够。

**训练侧 — n×n attention 矩阵（瞬态）→ FlashAttention**

- 朴素实现把 `S=QKᵀ` 和 `P=softmax(S)`（各 h·n² 元素）物化到 HBM：O(n²) 显存，长上下文直接爆（8k→128k，n² 让 attention 矩阵显存 ×256）。
- attention 算术强度（FLOP/字节）≈ d（头维 64-128），远低于 GPU 平衡点（H100 ≈ 300 FLOP/字节）→ memory-bound，算力空转。
- FlashAttention：tiling + online softmax，不把 n×n 物化到 HBM，显存 O(n²)→O(n)，**FLOP 不变（精确，非近似）**，靠减少 HBM 搬运量提速。对应"数学定义 vs 实际执行"——定义没变，变的是执行。

**推理侧 — KV cache（持久）→ GQA / MQA / MLA**

- 自回归解码（decode）一次吐一个 token；每步新 token 要 attend 到所有历史 token。把历史 K/V 缓存下来（KV cache）避免每步 O(n) 重算。
- KV cache ≈ `4·n·d_model·L` 字节/序列，随上下文长度 n 和并发 batch 线性增长。7B 级模型每 token ≈ 0.5 MB，32k 上下文单序列 16 GB，×32 并发 = 512 GB——碾压模型权重（才 14 GB）。
- decode 每步算力量极小（1×t 的 attention 行）却要读整个 cache → memory-bound。
- 解法：**Q 保持多头（保视角），只砍 K/V 的份数**——GQA 分组共享、MQA 全共享、MLA 低秩压缩，直接缩小 cache。

**共同点**：两头都在削 MHA 的"×h"复制，且都 memory-bound。FlashAttention（训练端不物化 n×n）与 GQA/MLA（推理端少存 K/V）不互斥，现代模型两层一起用。

### FFN，what & why

**和 attention 的分工**：attention 是"信息路由"——加权求和把别的 token 的信息搬过来，本质是聚合，不做重计算。FFN 是每个 token 的"独立思考"——对聚来的上下文做非线性变换。一个 layer = 先 attention（横向交流）→ 再 FFN（纵向加工）。FFN 是 position-wise 的：每个 token 独立处理，token 之间不混合。

**没有 FFN 会怎样**：纯 attention 堆叠很弱——能搬信息，但不能对单个位置做非线性变换。FFN 是模型算力和知识的主要所在。

**参数量对比**（base，单层）：attention 的 Q/K/V/O 四投影 4×512×512 ≈ 1.0M；FFN 的 W₁/W₂ = 512×2048 + 2048×512 ≈ 2.1M。FFN 占每层约 2/3，不是装饰，是容量主体。

**ReLU 避免层深度坍缩**：两个线性层中间若无非线性，`W₂(W₁x) = (W₂W₁)x`，塌成一个线性层，白叠两层、深度无意义。ReLU 让两层结构真正生效。

**维度流**：
```
X (attention子层输出)   n × 512
   │  每个token独立施加同一个FFN（position-wise）
   X @ W₁     W₁: 512×2048   →  n × 2048   ← 中间维
   ReLU                      →  n × 2048
   @ W₂       W₂: 2048×512   →  n × 512    ← 压回 d_model
```
输入 n×512，输出 n×512；2048 是中间维，既非输入也非输出。

### Decoder：两种 attention 与 n/m 两个长度

decoder 里有两个长度：**n = 源句长度**（encoder memory，prefill 定下、全程不变）；**m = 目标前缀长度**（decode 里从 1 长）。生成第 t 个目标 token 时 m=t（d=d_model）：

| 子层 | Q | K/V | attention 矩阵 | 输出 | token 长度 |
|---|---|---|---|---|---|
| masked self-attn | t×d | t×d（目标前缀） | t×t（causal） | t×d | t |
| cross-attn | t×d（decoder 侧） | n×d（encoder memory） | t×n | t×d | t（n 在 K/V 侧） |

decoder layer 的 token 长度 = m（目标前缀长），三个子层一路保持；n 只在 cross-attn 的 K/V 侧，不是 decoder 的 token 长度。

- **prefill = encode**：源句 n 个 token 一次并行编码 → memory（n×d_model），只算一次。
- **decode = decoder 生成**：目标端一次一个 token，m 从 1 长；每步 cross-attn 都复用同一份 encoder memory（n 固定）。
- 所以 n 是 prefill 一次定下、decode 全程反复查的；m 是 decode 里一步步长的。

（现代 decoder-only LLM 没有 cross-attn，prefill 和 decode 都在同一个 stack 对同一条序列做——prompt 长 n 的 prefill 后，decode 让序列长过 n。2017 是 encoder-decoder，多一个 cross-attn，所以 n 和 m 是两条不同的长度。）

### 与硬件的关联

> Transformer 的并行特性天然适合 GPU：所有位置的注意力计算可以同时进行（矩阵乘法），而 RNN 的逐时间步依赖无法利用 GPU 的大规模并行能力。这也为后来 FlashAttention 等 IO-aware 优化奠定基础——Transformer 的注意力是典型的 memory-bound 操作，计算量小而数据搬运量大。

### 关键公式

Scaled Dot-Product Attention：
$$
\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

Multi-Head Attention：
$$
\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h)W^O
$$
$$
\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)
$$

## 对我的启发

- 这是 FlashAttention 的前置基础，理解原始 Attention 机制才能理解 FA 优化了什么
- 注意力的"数学定义"和"实际执行方式"是两回事——Transformer 给了定义，FlashAttention 优化了执行
- 矩阵运算始终是深度学习的核心，从 QK^T 到 softmax → V，几乎所有现代 LLM 都在做这件事

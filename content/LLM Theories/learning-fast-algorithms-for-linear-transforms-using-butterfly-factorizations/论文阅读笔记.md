## 核心问题：什么叫"一个变换有快速算法"？

你有一个 N×N 的矩阵 T，输入向量 x，输出 y = Tx。朴素的矩阵向量乘法要做 N² 次乘加——因为 T 是稠密的，每个输出元素 y_i 都要跟 N 个输入做点积。FFT 把 DFT 的这个 N² 降到了 N log N。那问题是：怎么把这个"快"形式化？什么样的 T 能变快？快到什么程度？

稀疏分解就是答案：把 T 拆成若干个稀疏矩阵的乘积。假设你能把 T 写成：$$T = S_1 S_2 \cdots S_k$$
其中每个 $S_i$ 都是稀疏的（非零元素很少）。那么计算 $y = Tx$ 就不需要一次稠密乘法了，而是分 k步：$$v_k = S_k x, \quad v_{k-1} = S_{k-1} v_k, \quad \cdots, \quad y = S_1 v_2$$
每一步是稀疏矩阵乘向量，代价跟 $S_i$ 的非零元素数 $\text{nnz}(S_i)$ 成正比。总代价就是：  $$O\left(\sum_{i=1}^{k} \text{nnz}(S_i)\right)$$如果这些因子足够稀疏，总和远小于 N²，你就拿到了一个快速算法。FFT 就是这个模式的具体例子。DFT 矩阵 $F_N$ 本身是稠密的（N² 个非零元素），朴素乘法 O(N²)。但你刚才读的那条递归分解把 $F_N$拆成了 $\log_2 N$ 个 butterfly 因子的乘积，每个因子只有 2N 个非零元素。所以：$$\sum_{i=1}^{\log_2 N} \text{nnz}(B_i) = \log_2 N \times 2N = O(N \log N)$$
FFT 的 $O(N \log N)$ 不是凭空来的——它就是"稠密矩阵 $F_N$ 拆成 $\log_2 N$ 个稀疏因子"这个框架的直接产物。
反过来也成立：这是最优的框架，不是碰巧。论文里那段"令人惊讶的是，反之亦然"说的是：稀疏乘积宽度（SPW），也就是分解中所有因子的非零元素总数 $\sum \text{nnz}(S_i)$，被证明等价于最短线性直线程序（shortest linear straight-line program）的长度——差的只是一个常数因子。
线性直线程序就是一串形如 $v_i = a \cdot v_j + b \cdot v_k$ 的指令，每条指令做一次乘法和一次加法，$v_j, v_k$ 是之前算出来的中间结果。计算 $y = Tx$ 的最短直线程序长度，就是你能找到的最优算法的操作数下界。

  SPW = 最短直线程序长度（差常数），意味着：

  > 你能找到的最好的稀疏分解，就是你能找到的最好的快速算法。不存在一种"用别的思路比最好的稀疏分解更快"的算法。

  所以稀疏分解不是一个启发式的近似工具，它是"快速算法"这件事的定义本身——至少在代数复杂度理论的意义上是 provably optimal 的。

  为什么这是"恢复快速变换"这一节的预备知识？

  这篇论文的目标不是手写 FFT 公式，而是用梯度下降自动学出一个变换的快速算法。要学，就得先有一个参数化的搜索空间。逻辑链是这样的：

  1. 先定义"快速算法 = 稀疏分解"（这段预备知识在做的事）
  2. 再论证"在稀疏分解里搜索是最优的，不会漏掉更快的算法"（SPW = 最短直线程序）
  3. 然后把搜索空间收窄到一个具体的可学习参数化族——butterfly 因子的乘积（紧接着的 3.2 节）
  4. 最后用 SGD 去拟合 $T \approx B^{(N)} P^{(N)}$，如果拟合误差足够小，就"恢复"出了快速算法

  如果你跳过预备知识直接看 butterfly 参数化，你只会觉得"为什么要用这个特定结构？"有了这段铺垫，答案就是：因为稀疏分解是快速算法的最优描述符，而 butterfly 是稀疏分解里一个有递归结构、参数少、可学习的子类。它是从"什么算快"这个根问题上长出来的，不是拍脑袋选的。

## 路线定位：butterfly / FFT 与注意力效率 roadmap 的关系

> 以下辨证源于阅读 MLX（ISCA26）引言时的追问：MLX 引言 refs [3]-[9] 里，[9] FNet（用 FFT 替代 attention 的 token 混合）跟阶段3 roadmap 的 A/B/C/D 四条线是什么关系？结论经历了一次修正。

### 层次修正：FNet 不是正交旁支，是更上层的替换

初判把 FNet 归为"跟四条线正交的旁支"，这个说法不够精确。逐条验证：

- **A 线**（K/V 共享：MQA/GQA/MLA）改的是 Q/K/V 头结构。没有 attention 就没有 Q/K/V，整条线蒸发。
- **B 线**（稀疏/局部）改的是 attention mask、哪些 token 互相 attend。没有 attention 就没东西可稀疏。
- **C 线**（FlashAttention）本质是 attention kernel 的 IO 优化。没有 attention 就没有 kernel 可优化。
- **D 线**（服务/系统）最微妙。Orca 的迭代级调度概念能部分存活，但 vLLM/PagedAttention 的核心——KV cache 管理——是 attention 专属的，没了。

A/B/C 全死，D 只剩调度壳子。所以 FNet 不是跟 ABCD 并列的正交轴，而是**比 ABCD 高一层的选择**：先决定"token 混合用 attention 还是别的"，选了 attention 之后才有 A/B/C 这三个子问题。正确的层次是：

```
Level 0: token 混合器选择（attention / FFT / SSM / MLP-mixer）
Level 1（仅当选 attention）: A 线、B 线、C 线
Level 2（任何混合器）: D 线的调度部分、投影压缩、量化
```

FNet 是 Level 0 的备选项，不是 A/B/C 的同层兄弟。butterfly 投影压缩（refs [3][4][6]）才是真正正交的——它压缩的是 FFN/线性层，跟用什么 token 混合器无关（MLX 恰好就是把两者叠加的）。

### 为什么 FFT 替代 attention 没成主流

根因是精度，根因里的根因是**内容依赖性**。结构冲击是次生的。

attention 算的是 $A = \text{softmax}(QK^T/\sqrt{d})$，混合权重随输入变化——同一个 "bank" 在 "river bank" 和 "bank on Main Street" 里会 attend 到完全不同的邻居。这是动态路由，模型根据内容决定信息怎么流。FFT 算的是 $y = \text{FFT}(x)$，混合系数是固定的傅里叶基，不管输入是什么、每个 token 都以同一套固定方式跟所有 token 混合。这是静态路由。

语言里"哪些 token 该交互"是高度上下文相关的，固定变换区分不了。所以 FNet 在需要细粒度语义区分的任务（NLI、共指消解）上封顶偏低，MLX 自己的实验也确认了 2-3% 的精度下降。而且 MLX 这篇虽然是 FFT 的同情者，最终也没敢走 FNet 的全替换路线——它把 FFT 降级成**序列压缩工具**（丢掉高频分量、缩短序列后再做 attention），attention 还留着。连最想用 FFT 的论文都退回到了"FFT 辅助 attention"而不是"FFT 替代 attention"，这个撤退本身就很说明问题。

结构冲击（破坏 KV cache、不兼容 prefill/decode）是真的，但它是次生的——如果 FFT 的精度够好，产业界会去建适配它的服务基础设施；正因为精度封顶，没人有动力投资，于是基础设施缺位又反过来加剧不采用。根上还是精度。

### 反证：替换 attention 这条路没死，死的只是"用 FFT 替换"

Mamba（2023）也是替换 attention，用 selective SSM，但它的参数是输入相关的——保留了内容依赖性。所以它能上量（Jamba 等商用模型用了 Mamba+attention 混合）。对比之下，FNet 失败不是因为"替换 attention"这个方向错，而是因为 FFT 是内容无关的固定变换，丢掉了 attention 最核心的那个性质。Mamba 的存在证明 Level 0 的备选可以存活，但存活条件是你得把内容依赖性保住。

### 稀疏分解的代数最优性 vs 硬件现实

SPW = 最短直线程序长度的等价关系是**代数复杂度理论**层面的，隐含的计算模型是：每条指令 $v_i = a \cdot v_j + b \cdot v_k$ 花费一个单位代价，数的是操作次数，不涉及访存、并行、数据布局。

现代硬件（Tensor Core / 脉动阵列）是为**稠密 GEMM** 设计的：数据稠密、连续、对齐，操作强度（FLOPs/byte）极高。butterfly 稀疏因子的非零元素散布在固定跨步位置，灌进 Tensor Core 大量 lane 在乘零，各阶段间还要做 permutation（位反转重排），访存模式不规则，缓存局部性差。结果：FLOP 少了，但每个 FLOP 的代价变高了，吞吐反而下降。

这正是 MLX（ISCA26）存在的理由——它用 roofline 分析量化了这个脱节（FFT/butterfly 在 CUDA 核心上的操作强度远低于 Tensor Core 上的稠密 GEMM），然后提出换一种硬件（空间数据流架构）来兑现稀疏分解的算法收益。butterfly 论文说"稀疏分解 = 快速算法的最优描述符"，MLX 说"对，但只在操作计数模型下成立，换到真实并行硬件上需要协同设计才能兑现"。

## 一句话总结

> 提出面向 Triton 与 cuTile 的受控 GPU 算子基准 TileBench，覆盖 B200 上 45 个 AI 算子，统一 PyTorch 参考、dtype/尺寸扫描、autotune、roofline 与 NCU 诊断，系统对比两种 tile-based 编程模型的性能特征与瓶颈。

## 核心问题

- Triton 和 cuTile 两种 tile-based 编程模型在实际 AI 算子上的性能差异到底有多大？各自的优势场景是什么？
- 缺乏统一的基准框架来公平对比不同 tile-based DSL 的性能表现
- 如何在算子层面做细粒度的瓶颈诊断（roofline 分析 + Nsight Compute）

## 关键洞察 / 创新点

1. 构建了覆盖 45 个真实 AI 算子的受控基准，统一 dtype、尺寸、autotune 配置，确保对比公平
2. 同时集成 roofline 分析和 Nsight Compute 瓶颈诊断，将性能差异归因到具体的硬件瓶颈类型
3. 发现 Triton 几何平均较 PyTorch 快 2.7×、cuTile 快 2.2×；cuTile 在 Tensor Core / TMA 友好负载占优，Triton 在不规则与带宽受限算子更稳健
4. LLM 代码生成实验表明 Triton 的 token 效率更高，代码生成友好度更好

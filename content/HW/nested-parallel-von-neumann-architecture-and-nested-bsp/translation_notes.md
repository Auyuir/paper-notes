# Nested Parallel von Neumann Architecture and Nested BSP 原文翻译

## 3 统一总线硬件的六件事：把断崖变成缓坡

原则已经明确。下面我们转向实现这一原则的硬件，以及过去技术力有不逮之处。

先立目标。更远意味着距离更长、带宽更低、时延更高：这是物理规律，我们接受它。过去真正的失败不是“缓坡”，而是“断崖”。跨出机箱一步，带宽掉一个数量级，时延翻几倍。机架之内，表现得像一台机器；机架之外，各走各路。关键技术的任务，就是把这段断崖铺成缓坡，让指挥逐级下达，一层不落。

第一：一种协议，机架内外同一。

过去用的是两套。机箱之内，总线快、纳秒级，但天生短距，出不了机箱。机箱之外，网络可达远方，但每道边界都是收费站——拆包、查验、再打包。机架内说一种语言，机架间说另一种语言，每过一道边界就要转换一次。在大型集群中，超过 80% 的能量用于搬移数据，其中相当一部分就损耗在这些转换上。统一总线把“总线”与“统一”融合为一个协议，从封装一直贯通到自治域，端到端，全程无转换。

第二：让远端内存用起来像手边的内存。

过去搬移数据，意味着一层层爬到应用，再跨协议转换一次。TCP/IP 一个来回花掉几十微秒，大头耗在软件上。RDMA 大幅改善了这一点，但骨子里仍是“发一条消息、等一个回复”。Barrier 与 Reduction 全堵在这里，规模越大，堵得越厉害。我们换成了内存语义：原生 load 与 store，一致性由硬件处理。一次通信往返从几十微秒降到一百纳秒上下，约五百倍；单芯片 I/O 带宽达到 7.2 Tbps 量级。

第三：拆掉主从关系，这是对等平等的地基。

过去是主机下令、设备从命，也就是说一切都要经过一个中心。这种主从模式并非某条产品线的偶然，而是传统计算机设计的默认格局：CPU 为主、加速器为从，主机为主、设备为从，控制面独占发起权，其余人统统等待。队伍越大，中心越堵。添兵不加力——一加一小于二。本设计把 CPU、NPU、内存、存储与 NIC 放在同一条总线上，彼此对等：谁都能发起，谁都能响应。嵌套 BSP 每一层的 Barrier 与聚合，不必事事回中心汇报。没有这份平等，嵌套的作战计划就塌回主节点前的一条队列；有了它，嵌套并行冯·诺依曼架构便可扩展，而不存在单一咽喉。

第四：铜近光远，但语言不变。

铜已经撞上了墙。把每根线上的数据速率往上推，线就变粗、传得更近；把成千上万根铜缆捆起来，就粗得没法安装。所以第一代统一总线在设计上就同时兼顾电与光：近处用铜，保住时延；远处用光，保住规模；介质变了，协议不变。在光这一侧，我们选了近封装光学（NPO）。全电通路上二十多分贝的损耗，NPO 一步就去掉九到十一分贝；共封装光学（CPO）只能再拿掉大约三分贝。换来的是：光引擎可以作为独立模块来制造、测试和更换。时延为十纳秒级，整体成本比 CPO 低 40% 以上。这条路线如今已是 OIF 项目，由数十家伙伴共同推进 [7]。

第五：不要把士兵全塞进一顶帐篷。

旧的本能是往极限里装：芯片更大、机架更满。算力随面积增长，而 I/O 带宽与功率只随周长增长：越装，失配越重。散热更具体：一个兆瓦机架，光制冷就可能要几百平方米；一个吉瓦机房可能只装得下一千个机架，却要占一平方公里，水管拉出一公里长。机房的地皮便宜，机架里的芯片昂贵。所以我们不追兆瓦机架。我们让队伍敞开站列，再用光把它绑成一台机器：站得疏，算得紧；物理疏，逻辑紧。

第六：每一代，只打几场硬仗。

一次挑二十个物理极限，每个九成胜算，联合成功率也近乎为零。挑五个，就还能交付。选择攻下什么、把什么留待后续形态，这本身就是设计的一部分。
